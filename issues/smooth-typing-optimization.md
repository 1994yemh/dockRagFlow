# 前端流式输出平滑与性能优化

## 上下文描述
用户反映前端流式输出过程中存在卡顿，且字符有时会一次性蹦出十几个。这主要是由于大模型流式传输的网络抖动、后端缓存、以及前端在每次字符更新时进行全量 Markdown 解析与全局 Highlight.js 代码高亮重绘，严重占满 CPU 线程所致。

本项目采用**方案 1：纯前端队列缓冲与平滑吐字 + 增量防抖高亮机制**来进行全栈视觉调优。

## 计划步骤
- [x] 1. 在 `index.html` 中引入流式字符缓冲队列 `charQueue` 与平滑打字定时器/追赶机制。
- [x] 2. 改造前端 `sendMessage` 中的流读取逻辑，将接收到的 Token 送入队列而非直接更新渲染。
- [x] 3. 重构高亮与排版逻辑，避免每次吐字全量高亮，采用防抖高亮或仅在流结束时进行 Highlight.js 全量高亮，流期间使用轻量级样式区分。
- [x] 4. 优化 `marked.parse` 解析频率，引入轻量级节流，降低 DOM 树重绘开销。
- [x] 5. 测试并联调，验证打字匀速丝滑感。
